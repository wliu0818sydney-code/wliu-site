# 《我独自学习》

雅思听力 · 每日听写。

在线访问：<https://wliu0818sydney-code.github.io/wliu-site/>

一个纯静态的听写练习站：20 组共 500 个词，按 41 天排期安排新学和复习（做 5 天休 2 天，每组在第 +1、+2、+4、+7、+15 天复习）。支持听音写词、看中文写英文、待攻克（错词）练习和进度导入导出。另有两个独立的练习：听句概括和文章精读。

游戏元素只是现有进度的一层展示，不影响排期和判分：

- **每日任务**：当天排到的新学、复习、补学。
- **待攻克**：拼错或点“不会”的词，答对一次就移出。
- **EXP**：已掌握的词数（当前状态为“答对”的词）/ 500，数字都是真实的。
- **等级**：只由已掌握词数决定，一阶 0、二阶 50、三阶 150、四阶 250、五阶 350、六阶 450。如果答对过的词后来又答错，词数和等级会相应回落。
- **本轮结算**：每轮结束后显示本轮的真实数字；只有真的跨过等级线才显示升级。点“收下”关闭，有键盘时也可以按 Esc。网站本身没有音效；出声的只有语音朗读，以及访问者自己加载的视频。

非官方个人学习工具。与 IELTS（雅思）的主办方 British Council、IDP 和 Cambridge University Press & Assessment 没有隶属关系，也未获其认可，相关商标归其所有。站名化用了作品《我独自升级》的标题，与该作品及其权利方没有关联，也未获授权。

## 登录

打开网站先看到标题页，它是全站唯一中英双语的页面，其余界面都是中文。输入用户名登录，或者选择访客登录。

- 不需要密码，也没有账号：用户名只用来在这个浏览器里分开保存进度，不能跨设备同步。这台设备上输入同一个名字的人都能看到这份进度。
- 名字不区分大小写，最多 20 个字符。每个用户名有自己的听写进度、听写设置、听句概括记录和文章精读进度；主题是整个浏览器共用的。
- 访客用的是有用户名之前的那份记录，所以以前的进度都在访客里，用户名登录不会动它。
- 同一个标签页里只登录一次，刷新后还是这个用户；新开标签页要重新登录，上次的名字会自动填好。顶栏可以切换用户，练习进行中不显示切换按钮。

## 听句概括

任务窗口顶部可以切换到“听句概括”：听一句或几句英语，用自己的话写下意思。它的数据单独保存，不影响听写的排期、判分、EXP 和等级。可以用 `index.html#summary` 直接打开。

**原创素材**：`listening/summary-data.js` 里的 15 段短文（一句、两三句、短段各 5 段）都是为这个网站写的，内容是虚构或通用的，没有真实人物、机构或统计数字。

- 用浏览器的语音合成逐句朗读，句间有停顿，沿用听写里选择的口音。可以重听和慢速重听，遍数只在语音真的开始时才增加。
- 听的时候原文不显示。提交概括后才能看到要点、中英文参考概括和原文。
- 对每个要点自己选“听到”或“没听到”。**这是自评，不是 AI 判分**，文字不会发送到任何地方。
- 概括留空只会提示，不会留下记录。最近一次没听全的段落可以重练。
- 读不出声音时会明确说明，不会假装播放。这时可以选择阅读原文，但这一次不计入记录。

**自带视频**：粘贴自己的 YouTube 链接，仅供个人练习。

- 只接受 https 的观看、`youtu.be` 短链接、`/shorts/`、`/embed/` 地址，且必须有 11 位视频 ID，其他一律拒绝。
- 点“加载 YouTube 播放器”之前不会向 YouTube 发送任何请求。点击后，浏览器先从 `www.youtube.com` 加载 IFrame API 脚本，这一步 YouTube 可能写入 Cookie；播放器本身嵌在 `youtube-nocookie.com` 上，不自动播放。品牌和控件都留在播放器里，不覆盖也不隐藏，播放器不小于 200×200。
- 用“标记起点/标记终点”或输入 `分:秒` 选片段，“播放片段”放到终点后暂停。YouTube 文档说明跳转可能提前最多约 2 秒。
- 字幕由你自己在播放器里打开来核对。本站不读取、下载、代理或保存视频和字幕。
- 只保存视频 ID、自己写的标题、起止时间和笔记，可以删除，也可以导出 JSON，再从同一页导入恢复。最多 200 条，满了要先删除才能保存新的。
- 视频不允许嵌入时会说明原因，并给出到 YouTube 打开的链接。
- 这个模式需要通过 `http(s)` 地址访问，直接双击打开文件时 YouTube 可能拒绝嵌入。
- 没有 TED 专用播放器，也没有预设任何视频或讲稿。

此模式仅供个人练习；视频和字幕归原权利方所有，本站不存储视频或字幕，请遵守来源平台与内容方的规则；TED 等内容可能禁止截断、商业使用或用于 AI，公开传播或盈利前请先取得许可。

## 文章精读

任务窗口顶部的第三个标签，也可以用 `index.html#article` 直接打开。每篇文章是一个单元，用这篇文章里挑出来的词走三步，前一步做完才解锁下一步，这样从词到句子再到整篇，一步步来。

1. **词汇听写**：听音拼写这篇文章的词。规则和每日听写一样：回车提交，输入框空着时回车重听，可以慢速再听和看中文提示，点“不会”看答案，判分规则相同，词组也一样。没答对的词排到最后再来，每个词都答对一次才算做完。口音和听写方式沿用“每日听写”里的选择。
2. **写句子**：先填句子，再造句。
   - **填句子**：看中文翻译、语法提示和带空的句子，写出这个词在句子里的准确形式，不区分大小写。页面会说明要填的是第 1 步听写过的词，也就是文章原文这里用的词，并给出开头两个字母。写成和这个词差得比较远的词不算对，但不会显示成拼错，因为它放在句子里也可能说得通；这个词的其他形式和拼写小错仍然逐个字母改正。答完显示整句，可以听整句。没答对的题排到最后再来，答对一次才算做完。一句话里可能有好几个空，还没答对的空会一直遮住；这样的句子要等里面的空都答完才显示整句、才能听，否则读出来就把后面的答案说了。
   - **造句**：看句型、目标词和中文意思，自己写一句。**网站判断不了语法**：没有服务器，也没有 AI，不会给句子打分。它只看四件表面的事（有没有写、有没有用目标搭配、开头是否大写、结尾有没有标点），只提醒，不拦人。然后显示范句和自查清单，可以对照着改，改好了再标记完成。
3. **阅读原文**：按段显示全文，每段有字母标记。学过的词（包括文章里的各种形式）都高亮，而且都是真正的按钮，键盘也能按；按下后显示中文和词性，并读出这个词。可以朗读当前这一段，也可以随时停止。点“读完了”结束这一篇。

其他规则：

- 做完一步会有一个按钮直接进入下一步。做完的步骤可以回看和再练，再练不会改变第一次的成绩。可以重新开始一篇（按两次确认），这会清空这一篇的进度和写的句子。
- 学完显示这一篇的真实数字：听写第一次拼对 x / y、填句子第一次填对 x / y、写下的句子 n 句。“写下的句子”只说明写了多少，不代表写对了多少。
- 文章里的词和 500 词词库分开，不影响每日任务、排期、待攻克、EXP 和等级。这里没有音效。
- 进度按用户名保存，刷新后回到原来的位置。练习中和听写一样不显示切换用户。读不出声音时会明确说明，不会假装播放。

### 添加一篇文章

只要在 `listening/article-data.js` 的 `articles` 数组里加一项，不用改别的文件。列表、步骤和进度都由这份数据生成。

```js
{
  id: "my-article",       // 小写字母、数字和连字符。进度靠它保存，发布后不要改，也不要给别的内容重复使用
  title: "文章标题",
  paragraphs: [
    { label: "A", text: "这一段的原文，写成一行。It has a big impact on us." }
  ],
  words: [
    { en: "impact", zh: "影响", pos: "n.", forms: ["impact"], accept: ["impact"] }
  ],
  cloze: [
    { id: "my-article-c-impact", word: "impact", para: "A", before: "It has a big ", answers: ["impact"], after: " on us.", zh: "它对我们影响很大。", note: "" }
  ],
  writing: [
    { id: "my-article-w-impact", word: "impact", pattern: "have a big impact on + 名词", prompt_zh: "睡眠不足对学生影响很大。", mustInclude: ["impact on"], models: ["Lack of sleep has a big impact on students."], check: ["介词用 on，不用 to 或 for"] }
  ]
}
```

- `paragraphs`：`label` 不能重复。
- `words`：要听写的词，`en` 不能重复。`forms` 列出这个词在文章里出现的每一种写法，大小写也要一样，整词匹配才会高亮。`accept` 是听写接受的拼写，第一个必须是 `en`，后面的也算对。词组直接写，例如 `per capita`。可以再加一个 `homo` 列表，写同音词，例如 `homo: ["whether"]`：只靠听的时候写成它也算对，页面会提示要的是哪个词，和每日听写一样。
- `cloze`：每个词正好一题。`before + answers[0] + after` 必须是 `para` 那一段里一字不差的一句话。`answers` 里后面的是也算对的拼写。`note` 每题都要有：答案变了形时写提示，例如“这里是复数”，没变形时写空字符串 `""`。`cloze` 和 `writing` 的 `id` 格式和文章的 `id` 一样。题目按数组顺序提问，共用一个句子的题尽量分开，先问的词不要被前面的句子说出来。
- `writing`：`word` 是句型的关键词，可以不在 `words` 里。`mustInclude` 是目标搭配，写到其中一个（整词、不分大小写）就算过了这项检查。`models` 的每一句都要能过四项检查。`check` 是让学习者自己对照的要点。
- 所有文字都按纯文本显示，写进去的 HTML 不会生效。
- 新的一项和前一项之间要有逗号。文字里的英文直引号 `"` 要写成 `\"`，或者换成弯引号 `“ ”`。否则整个文件读不出来，所有文章都不会显示。

加完后用下面“本地预览”的服务器打开 `tests/logic-test.html`：它会检查所有文章的数据，有问题的地方都列在 `FAIL` 后面，文件读不出来时也一样，并写明行号。数据不完整、无法显示的文章不会出现在列表里，列表上会提示有几篇被跳过。

以后给已发布的文章加词：还没做完那一步的人会接着练新词，已经做完的不受影响。

## 隐私与第三方服务

- 本站没有服务器、统计或广告。用户名和练习记录只保存在访问者自己的浏览器里。自己写的概括、笔记、标题和句子不会被朗读，也不会发送到任何地方；粘贴的链接里的视频 ID 在点击加载后会发给 YouTube。
- 网站托管在 GitHub Pages，GitHub 可能记录访问日志。
- 部分浏览器的语音由其厂商在线合成，发送的只是本站的单词和短文。
- “自带视频”使用 YouTube API 服务。点击加载后浏览器才会连接 YouTube，这时 YouTube 可能写入 Cookie。点击加载即表示同意 [YouTube 服务条款](https://www.youtube.com/t/terms)，数据处理适用 [Google 隐私权政策](https://policies.google.com/privacy)。

## 本地预览

项目是纯静态文件，没有框架和构建步骤。在项目目录里启动任意静态服务器：

```
python -m http.server 8000
```

然后打开 <http://localhost:8000>。

也可以用任何其他静态服务器。直接双击 `index.html` 也能运行。

## 部署到 GitHub Pages

1. 把这个目录推送到一个 GitHub 仓库的 `main` 分支。
2. 打开仓库的 **Settings → Pages**。
3. 在 **Source** 里选 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`，保存。
4. 等一两分钟，网站就会出现在 `https://<用户名>.github.io/<仓库名>/`。

所有路径都是相对路径，部署在子目录下也能正常工作。

## 进度保存在哪里

- 进度只保存在访问者自己的浏览器里（`localStorage`），不会上传到任何地方。在 `github.io` 上，同一账号的其他项目站点和本站共用这份浏览器存储，所以以后在这个账号下再开站点时，不要清空 `localStorage`。
- 换设备、换浏览器、清除浏览器数据或更换网站域名后，进度都不会保留。可以在页面的“设置”里用“导出进度”备份，再用“导入进度”恢复。
- 导入是整体覆盖，不会合并。
- 每个用户名的记录分开保存：听写、听写设置、概括记录、文章进度和它们的另存副本都用“原来的键 + `@` + 小写并经 URL 编码的用户名”，例如 `ielts-dictation-v1@alice`；访客用原来的键。
- 同时开两个标签页练习听写或文章精读时，后保存的进度会覆盖先保存的。
- 文章精读的进度单独保存在 `wliu-article-v1` 下，但包含在听写的“导出进度”“导入进度”和“清空进度”里。导入的文件里有文章进度时会一起覆盖（没有开始任何文章时导出的文件也一样，确认时会写“0 篇”）；旧文件里没有这部分，或者这部分读不出来（包括里面的文章都已不在网站上）时，听写照常导入，现有的文章进度保持不变，确认导入时会说明。如果存储的内容读不出来，原始文本会先另存到 `wliu-article-v1-recovery`，页面会提示并可以导出它；“清空进度”会连这份另存的内容一起删除。
- 听句概括的记录单独保存在 `wliu-listen-summary-v1` 下，不包含在听写的“导出进度”里，在它自己的页面里导出和导入。导入只添加还没有的内容，不会覆盖或删除已有记录。如果存储的内容读不出来，原始文本会先另存到 `wliu-listen-summary-v1-recovery`，页面会提示并可以导出它。
- 单词发音使用浏览器自带的语音合成。如果约 8 秒内没有开始发音，页面会提示，这时可以换一种口音或改用“看中文写英文”。微信等应用内浏览器也可能读不出声音。

```js
art: { left: "", right: "" }
```

- 两个都留空时，显示默认的学习者：夜间在屋顶上，日间在雪崖上。
- 填入图片路径（相对于 `index.html`，例如 `assets/my-art.png`）后，图片会显示在主栏对应一侧和入场画面里，并在两个主题下都取代学习者；没填的那一侧什么都不显示。窗口宽度小于 1280px 时主栏两侧不显示插图，图片只出现在入场画面里。
- 图片只作装饰，替代文字为空。图片加载不出来时会被移除；全部加载失败时，学习者会重新出现。

**这里只能使用原创，或已取得正当授权的图片。** 不要使用来自动漫、漫画、游戏等已有作品的角色或截图，也不要使用无法确认授权的网络图片。

## 视觉与版权说明

整站是一场以听力为主题的夜间风暴：近黑的紫色夜空、深紫面板，电光紫和淡紫白作强调色，只留一种暖色给最重要的数字和标记。默认是夜间；只有访问者选过“日间”才会保存并显示日间。

日间主题是一片冰蓝雪原：淡蓝的天空、半透明的冰蓝窗口、深青墨色的文字和清晰的窗口边框，暖色只有一种（重要的数字、标记和学习者的围巾）。背景最上方是一整座由音频波形冻结成的冰川山脉：山脊线就是紧挨着的波形竖条，有响亮的段落也有几乎无声的停顿，竖条之间只隔着窄窄的冰缝，下方一条水平的雪线，雪线下的冰里是同一段波形的倒影。再往前是两层随距离变淡的低矮雪丘和吹散的飞雪。这张图保存为 `assets/snowfield.svg`（2400×1000，整条山脊都在画面上部），只用纯色和渐变、没有滤镜，作为一张图片放在固定的背景层上，夜间不会加载。

雪崖上的学习者（`assets/learner-snow.svg`）是同一个看不到脸的学生，沿用夜间人物自己的身体形状，换成深色墨线，画得很小，戴兜帽和耳机，背着双肩包，手里拿着书；没有电弧，只有一条短围巾和卫衣下摆被风吹向左边。同一时间只显示一个人物。人物只站在主栏外侧和入场画面里窗口下方，不与文字或控件重叠；窗口宽度小于 1280px 时主界面不显示人物。切换主题不刷新页面。

屋顶上的学习者（一个从背后偏侧看到的学生，看不到脸，戴兜帽和头戴式耳机，背着双肩包，两脚大步站开，风把衣摆和背包带吹起，头微微抬向天空，一只手按着耳机，另一只手把一本书拿在身侧）和全部界面（带紫色辉光的玻璃窗口边框、EXP 条、任务卡、结算窗口）都是为这个项目绘制的。配色和氛围受到暗紫风暴、冰雪海报和游戏“系统窗口”这类风格的影响。人物的紫色轮廓光带一道白热的亮边，电弧沿声波的弧线从两只耳罩向上、向外散开，并洒出细小的墨点。

夜间背景（横穿天空的斜向墨笔、墨点、月亮和深紫色城市剪影）、日间背景、波形、图标和插图全部由 CSS、SVG 和 Canvas 生成。除了载入动画的两个视频（素材来源见“载入动画”一节），仓库里没有第三方的图片、音频、视频或字体文件。墨笔在宽屏的主栏后方会淡下去，并在天际线之前收尽；窄屏上月亮和亮笔触会落在窗口后面，所以窄屏窗口几乎不透明，文字始终放在不透明度很高的窗口里。页面代码发出的外部请求只有“自带视频”里由访问者点击后才加载的 YouTube 播放器。

动效很少：夜间，屋顶学习者的电弧大约每 23 秒轻轻暗一下；窗口宽度不小于 1100px 时，月光大约每 37 秒柔和地亮两下，然后静止。日间，雪崖上学习者的围巾和衣摆大约每 19 秒被风吹动一下；窗口宽度不小于 1100px 时，主栏两侧有 10 片雪花缓缓飘落，只改变位移和透明度。没有任何东西每秒闪烁超过 3 次。系统开启“减弱动态效果”时这些动画完全关闭，练习进行中也保持静止。
